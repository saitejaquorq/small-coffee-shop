# Small coffee shop website where

Build a small coffee shop website where customers browse the menu and place an
order for pickup. There are no customer accounts: every order is a guest order.

Who it's for:
- Customers (guests): browse the menu, add items to a cart, adjust quantities,
  and place the order without signing in. On placing the order they get a cart
  order ID to take to the kiosk.
- Cafe staff: see incoming orders with their items and order ID so they can
  prepare them.
- Admin/owner: manage the menu (add, edit, remove items and prices).

Core behaviour it cannot ship without:
- Show the menu with items, descriptions, and prices.
- Add items to a cart, change quantities, and remove items.
- Place the order as a guest and generate a unique cart order ID.
- Save every order (items, quantities, order ID, time) to the cafe's own
  database.
- Let staff view placed orders by order ID.

What it works with:
- Standalone. The cafe's own database is the only store. No external systems.
- Payment is out of scope of the website. The customer pays at the kiosk by
  giving the cart order ID; the website never takes payment and holds no
  payment data.

Scale and constraints:
- One coffee shop, small menu, small order volume.
- Web-based, mobile-friendly for customers ordering on a phone.
- No hard launch deadline.

## Running it

```bash
npm install
npm run dev
```

`npm run build` bundles the app; it does not typecheck. The screens were generated, and a
generated screen that renders correctly can still not satisfy `tsc` -- usually an untyped
`useState({})` that is then read for named fields. Deployment would fail on that, which is
a poor reason not to ship a working prototype.

`npm run typecheck` runs `tsc --noEmit` when you want it, and is worth fixing before this
becomes a codebase anyone maintains.

## Checks and tests

- `npm run lint` / `npm run lint:fix` -- ESLint over the whole app; `lint:fix` applies the
  fixes it can. The platform runs `npm run lint` as a gate during development, so keep it green.
- `npm run test` -- Vitest component tests, beside the components they cover.
- `npm run test:e2e` -- Playwright acceptance tests from the `e2e/` folder beside `src/`.
  `npm run test:e2e:install` fetches the browser first. With `E2E_BASE_URL` set it runs against
  that deployed URL; without it, Playwright builds and serves this app and runs against that.

## Layout

- `src/screens/` -- one module per approved screen.
- `src/App.tsx` -- the navigation shell and the route table.
- `src/lib/ui.tsx`, `src/lib/icons.tsx` -- the component and icon vocabulary
